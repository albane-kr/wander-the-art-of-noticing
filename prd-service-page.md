# PRD — Wander Sessions Service Page  
*A new page for discovering, filtering, and downloading guided walking sessions*

---

## 1. Purpose
The Sessions Service Page allows Wander users to browse, filter, and download guided walking sessions tailored to different environments.  
The page must feel like a quiet library — spacious, tactile, and grounded.

---

## 2. Goals
- Provide a calm, intuitive way to explore new sessions  
- Allow filtering by **environment type** (multi-select)  
- Enable downloading sessions directly to the Wander device  
- Maintain Wander’s brand identity: tactile, quiet, grounded, honest, accessible  

**Success metrics**
- Number of session downloads  
- Filter usage  
- Time spent browsing  
- Returning visitors  

---

## 3. Target Audience
- Existing Wander users  
- Curious visitors exploring Wander’s content ecosystem  
- Partners evaluating Wander’s long-term content strategy  

---

## 4. Core Experience
The page should feel like browsing a curated set of walks — not a digital store.

**Flow:**  
Hero → Filters → Sessions Grid → Session Detail → Download → Confirmation

---

## 5. Page Structure & Content Requirements

### 5.1 Hero Section
- **Headline:** “Walks shaped by the world around you.”  
- **Subheadline:** “Explore guided sessions designed for different environments.”  
- Background: Parch or Slate  
- Optional macro texture image  

---

### 5.2 Filter Bar
Multi-select filters representing environment types.

**Environment Filters**
- Park  
- City  
- Forest  
- Seaside  
- Lake  
- Riverside  
- Countryside  
- Indoor (optional future category)  
- Mixed environments (e.g., “Park → Street → Park”)  

**Filter behavior**
- Visible chips (no dropdowns)  
- Calm, tactile interaction  
- Sage = active, Slate = inactive  

---

### 5.3 Sessions Grid
Each session card includes:
- Title  
- Environment tags  
- Duration  
- Short description  
- Download button  

Imagery: macro textures only.

---

### 5.4 Session Detail Page
Includes:
- Title  
- Environment(s)  
- Description  
- “What you’ll notice” list  
- Audio preview  
- Download button  

---

### 5.5 Download Flow
- Modal or inline confirmation  
- Calm, minimal  
- No upsells  

---

## 6. Visual & Brand Requirements

### Colours
- **Parch** (#F4F1EB) — primary background  
- **Slate** (#2B2B28) — text, anchors  
- **Sage** (#6D836E) — accents, active filters  
- **Terra** (#BF7251) — single highlight per layout  
- **Sky** (#EACCC1) — info surfaces  

Never use pure white or pure black.

### Typography
- **Cormorant** for titles and headings  
- **DM Sans** for body, labels, UI  
- Sentence case only  
- Generous spacing and line-height  

### Imagery
- Macro textures  
- Natural surfaces  
- Soft Northern light  
- No people  
- No wellness clichés  

---

## 7. Technical Requirements
- HTML5, CSS3, minimal JS  
- Client-side filtering  
- Responsive grid  
- Lazy-loaded images  
- WCAG AA accessibility  

---

## 8. Risks & Constraints
- Must avoid feeling like an app store  
- Must avoid overwhelming users  
- Must maintain brand quietness  

---
